| 0.13.0 | 2026-09-07 | **yes — 2026-09-07, bench** | **Fix: the control loop was stalling.** The per-tick CSV line is written from inside the control tick, and a USB CDC write **blocks** while the host is not draining the port. Measured with nothing reading serial: **401 ms average tick with one stall of 24 seconds**, against a designed 100 ms. After `Serial.setTxTimeoutMs(0)`: avg 100.0, min 100, max 100. This was the real cause of "simulation is not updating the values", and on a real skid an unplugged laptop would have done the same to a running pump. **Fix: no endpoint reporting live state sent a cache header** — clients were free to serve a stale reading, which on `/status` means a page showing a seconds-old pressure with no indication. All live endpoints now send `Cache-Control: no-store` via `sendNoCache()`, and every page fetch passes `cache:no-store`. **Simulated VFD registers:** the sim reported a status word of `0x0000` forever, so trips, trip codes and the ready bit were dead everywhere. It now *builds* a status word and decodes it through the same `decodeStatus()` the Modbus path uses; heatsink temperature (first-order thermal rise) and raw AI1 counts are modelled too, and `pollDrive()` reads regs 20 and 24 on the real path. **Fault injection** (`/fault`, simulation only): inject any trip code on either drive. A tripped lead drive also invalidates the transducer that lives on its AI1, so the loop freezes and holds the pumps — the real failure, simulated. Verified 4/4 deterministic. **New Sim screen** (`/sim`, 5th tab) — plant controls, 1-or-2 pump selector, per-drive register table and fault injection, moved off System. **Pump profiles** (`pump_profile.h`): a strict subset of settings describing the PUMP — curve, speed limits, cap table and new motor nameplate (hp / volts / FLA / rpm). Applying one deliberately leaves setpoint, sleep and staging alone, because those belong to the installation. Three built-in templates plus four user slots in NVS, with JSON export/import. `Settings` fields appended, so no tuning is lost. |

| 0.11.0 | 2026-09-07 | **yes — 2026-09-07, bench** | **Simulation is a runtime mode, not a build.** Toggle on the System screen, with a 1-or-2-pump selector, so the real control block, sleep state machine and staging can be watched against a modelled plant on any board — speeds staying matched through a stage up and down, sleep and wake cycling, the operating point tracking across the envelope plot. The compile-time `SIM` macro is now only the factory default for blank NVS. **Safety:** switching simulation on drops `gEnable` and writes stop / 0 Hz to any real drive on the bus *before* the switch — a drive is never left running against invented feedback, and never left to trip on its own P-36 watchdog, which would stop it as a fault someone has to go and reset. Switching it off rescans the bus. `simOn` persists (a demo board stays a demo board) but `gEnable` still does not, so a reboot in simulation comes back stopped. Config import/export deliberately does **not** carry `simOn` — restoring a config must not put a field board into simulation. `Settings` fields are appended, so no tuning is lost. **Fix:** the Network screen re-toasted the boot message (`AP FCW-PUMP at 192.168.4.1`) every 5 s forever, because `loadNet()` polls and `gNetLog` is state, not an event. | 0.8.0 | 2026-09-07 | not yet | **CAN gateway — the board impersonates the drive to the AIO skid PLC.** No CODESYS changes: the CR1082 keeps talking CANopen to node 1, and this board answers it, forwarding commands to the real E3 over Modbus. Drive parameters are *shadowed*: P-01/P-02 are stored, echoed on read-back, and enforced here by clamping the speed reference, which sidesteps the E3's undocumented Modbus parameter scaling. ## Versioning

- **patch** — fixes, tuning, comments
- **minor** — new feature, new setting, changed web API
- **major** — first field deployment, then breaking changes only
