# Version log

Bump `FW_VERSION` in `pumpsaver.ino` on every change pass. See `CLAUDE.md`.

| 0.9.0 | 2026-09-07 | **yes — 2026-09-07, bench** | **Diagnostic max-Hz override + drive connection bubbles.** A 0–100 % slider in the Run card that, while engaged, **replaces** the cavitation cap and `maxHz` as the speed ceiling (100 % = 60 Hz, 0 % = stopped) and drops the minimum-speed floor to 0, so a pump can be walked all the way down on the bench. It lives in `PumpIn`, not `PumpCfg` — the same reasoning that keeps `gEnable` out of NVS: it defeats a protection, so a reboot must always come back with the cap enforcing. Sleep is suspended while engaged (the gates key off `hzCmd` and would otherwise sleep mid-test), the run bit drops at 0 % rather than holding the drive energised against a zero reference, and a red banner sits at the top of the page the whole time it is on. The ceiling is applied inside the PI clamp so anti-windup already accounts for it. `out.capHz` still reports the **real** cavitation cap while overridden — the override is not written back over a measurement. New `/ovr` endpoint; `ovr`/`ovrPct` in `/status`. Slider applies on release, not while dragging. Two green/red bubbles at the top of the page show per-drive link health, green only when the drive both answers reads **and** accepts writes. |
| 0.8.3 | 2026-09-07 | **yes — 2026-09-07, bench** | **First real-drive build — `SIM 0`.** Bench bring-up against an actual E3. **Write results are no longer discarded:** `commandDrive()` called `rtu.writeMultiple()` and threw the return away, so a drive that answered reads but refused writes (wrong P-12, locked parameter set) was indistinguishable from a healthy one. `Drive` gains `writeOK` / `writeFails`, the transition is announced on serial (`drive at 2: writes OK`), and both appear in `/status`. CSV log extended with the raw Modbus evidence per drive — `d1Hz,d1A,d1st,d1rd,d1wr` and the same for drive 2 — so a capture proves reads and writes rather than implying them. `gEnable` is false at boot and never persisted, so this build reads continuously and writes only stop / 0 Hz until someone enables it. |

The version block moved above the initialiser, with a comment saying why it has to stay there. Latent since 0.6.0 added `net.h` — no version between 0.6.0 and 0.8.1 was ever built, so it was never caught. Also on this pass: `build.ps1` now finds `arduino-cli` under `$env:LOCALAPPDATA\Programs\arduino-ide` (Arduino IDE 2.3.10 installs per-user, not to `C:\Program Files`), so neither path in it is machine-specific any more. |

| 0.8.0 | 2026-09-07 | not yet | **CAN gateway — the board impersonates the drive to the AIO skid PLC.** No CODESYS changes: the CR1082 keeps talking CANopen to node 1, and this board answers it, forwarding commands to the real E3 over Modbus. TX PDO1 is a verbatim copy of Modbus registers 6/7/8/24 — the E3 carries the same words in the same units on both links (9.2), so nothing is decoded and re-encoded. Drive parameters are *shadowed*: P-01/P-02 are stored, echoed on read-back, and enforced here by clamping the speed reference, which sidesteps the E3's undocumented Modbus parameter scaling. Standard objects are stored on write and returned on read, so the ifm CANopen Manager's startup configuration is agreed with rather than guessed at. If Modbus dies the board stops transmitting, so the PLC's own watchdogs trip. **Listen mode** captures a real bus to a frame log at `/can` — use it to read the drive's true 0x1018 identity before going live. |
| 0.7.0 | 2026-09-06 | not yet | **Config export / import.** `/export` downloads every setting as named JSON; `/import` accepts a pasted config. Named fields rather than the NVS blob, so a file written today still imports into later firmware — unknown keys ignored, missing keys left alone, everything re-clamped on the way in. **Passwords are never exported**; the network block carries SSID, broker and topic so a replacement unit is one paste from configured, then the two secrets get typed in on the board. Clamp limits moved into one `cfgClamp()` shared by `/set` and import so they cannot drift apart. |
| 0.6.0 | 2026-09-06 | not yet | **Station WiFi + MQTT telemetry.** Radio now `WIFI_AP_STA`: the FCW-PUMP config AP stays up permanently and the station side joins the site network, so the page is reachable whether or not that network works. Network settings live in their own NVS namespace (`psnet`), *not* the settings blob — a broker or SSID change no longer resets pump tuning. WiFi and MQTT run on a dedicated FreeRTOS task on core 0, so a blocking broker connect can never touch the control tick. Telemetry is publish-only with a retained online/offline last will; nothing is subscribed, so the network cannot command a pump. New `/net`, `/scan` endpoints and a Network card with an SSID picker. |

## Versioning

- **patch** — fixes, tuning, comments
- **minor** — new feature, new setting, changed web API
- **major** — first field deployment, then breaking changes only
